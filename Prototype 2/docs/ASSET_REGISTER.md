### React Three Fiber notes

- The official introduction describes R3F as a React renderer for Three.js: JSX elements such as `<mesh>` create Three.js scene objects, while React components can package reusable, stateful scene parts. The `Canvas` component sets up the scene and camera and manages rendering. The first-scene guide demonstrates geometries, materials, lights, props, and pointer interactions.
- The official docs pair R3F v8 with React 18 and v9 with React 19; the current v9 package manifest requires React/ReactDOM 19 and Three.js `>=0.156`. The live docs version selector showed v9.8.2, while the repository's `master` package manifest reported v9.8.1. v10 is marked alpha and changes the default renderer to WebGPU with a rewritten frame scheduler. Verify the actual release and peer dependencies when the project chooses its framework and versions; `site-next/` has not been scaffolded yet.
- Real-time WebGL can be costly on weaker phones and can use battery while continuously rendering. The R3F performance guide recommends on-demand rendering for scenes that can rest, reusing geometries/materials and cached loaders, instancing repeated objects, level of detail, staged model loading, and adapting resolution/effects to device performance. Its pitfalls guide advises mutating Three.js objects in `useFrame` with frame deltas rather than calling React `setState` on every frame.
- Keep essential copy, navigation, and controls in semantic HTML outside the canvas. Treat 3D as an enhancement: provide a useful static/non-WebGL fallback, support reduced motion, and verify keyboard and touch alternatives before adoption.
- Do not add R3F just to animate a simple decorative element; CSS or native browser features may be lighter. Select it only if an approved design needs a real interactive 3D scene.

### Spline notes

- **Live site and product flow (reviewed 2026-10-25):** The homepage is a dark product landing page with a sticky navigation bar, colorful floating 3D primitives and a small animated character around the “Make anything 3D” hero, plus an AI prompt field. Below it are remixable community scenes, customer proof, feature demonstrations, integration/export targets, tutorials, and documentation. The prompt field was not used, and the editor/account flow was not entered. The visible sections present Spline as an authoring and publishing tool rather than a website template.
- **What the product does:** Spline's browser-based 3D editor covers modeling, materials, lighting, cameras/effects, animation, physics, particles, and event-driven interactions. Its event system includes states, timeline animation, game controls, variables, APIs, and webhooks. The separate Hana editor is a 2D canvas for UI and motion work, with frames/auto layout, vector networks, visual effects, and the same interaction model. Both editors support collaboration and AI-assisted creation/editing. Community examples cover interactive sites, product design, branding/marketing, gamified pieces, mockups, logos, characters, and other 3D scenes.
- **Ways to publish:** A Spline Public URL is hosted by Spline and can be embedded in an iframe. `<spline-viewer>` is a native web component that can work without an iframe; its global mouse/follow/look-at/scroll interactions can respond to the full page, and the viewer lazy-loads its canvas when visible by default. Exported code paths include Vanilla JS, Three.js, React, Next.js, and React Three Fiber. The official docs say scene animations and events are enabled only for the Vanilla JS and React export paths. This means the R3F route is useful for bringing scene geometry into an R3F codebase, but should not be assumed to preserve Spline's built-in event animations unchanged.
- **What the official GitHub code does:** [`splinetool/react-spline`](https://github.com/splinetool/react-spline) is an MIT-licensed React wrapper, not the Spline editor. Its `Spline.tsx` component creates the Spline runtime on a canvas, loads the scene URL, registers optional mouse/keyboard/start/look-at/follow/scroll callbacks, provides loading children and a parent-sized canvas, and disposes the runtime on unmount. It defaults `renderOnDemand` to `true`, exposes the loaded runtime for scene-object lookup/event control, and documents lazy loading for the React app. [`splinetool/r3f-spline`](https://github.com/splinetool/r3f-spline) is a separate MIT-licensed hook: `useSpline()` loads a Spline scene and returns its nodes and materials for use as React Three Fiber meshes. Both packages still depend on Spline's runtime/export formats and on their respective React/Three.js dependencies. No source for the hosted 3D/Hana editors was identified in the official repositories reviewed; no repository code was copied.
- **Formats:** The FAQ lists OBJ, FBX (including animation/rig import), STL, GLTF/GLB, and `.spline` imports; image, partial SVG, video, audio, and Gaussian-splat inputs are also supported. Scene outputs include public/viewer embeds, code, `.spline`, GLTF/GLB, STL, USDZ, still images, and video/image sequences. The exact export options depend on the file and plan.
- **Performance and accessibility:** Spline's Performance Panel estimates export size and loading time and reports object/clone/boolean counts, polygons, materials, lights, post-processing effects, and textures. The docs recommend trimming geometry and other scene costs. A published real-time canvas still needs device testing because 3D uses more CPU/GPU than a normal 2D interface. For SIROSIU, keep key content and controls in semantic HTML, offer a useful static fallback where the scene is optional, and test touch, keyboard, reduced-motion, and phone behavior. These are project recommendations, not features supplied automatically by Spline.
- **Pricing and usage terms (checked 2026-10-25):** The current pricing page lists Free at $0 with limited personal files and watermarked web exports; Hobby at $12/seat/month billed annually or $15 monthly with no watermark on web exports; Pro at $25/seat/month billed annually or $30 monthly with no watermark on web embeds; and Enterprise at custom pricing with code and self-hosted exports. It is not a substitute for the site build, not a general source of automatically cleared third-party assets, and not required for a 2D-led design. The most promising connection to the first resource is Spline authoring plus the official `r3f-spline` bridge, but the built-in animation/event export limitation and plan/data terms need to be resolved before adoption. ### Detailed review — live documentation and source (2026-10-25)

- **How the docs work:** The live page uses a dark, three-column documentation layout: search and repository/community links at the top, a left navigation grouped by Getting Started/API/Advanced/Tutorials/Development, a right-side page outline, and a version selector at the bottom of the navigation. The Introduction page includes package-manager tabs, runnable examples, JavaScript/TypeScript code tabs, an expandable React Native example, and a CodeSandbox preview. I switched the install tab to npm and expanded the TypeScript example; the command and typed sample update in place. This is a useful learning interface, not a website template or a collection of reusable visual sections.
- **What R3F does:** R3F is a React renderer that maps JSX such as `<mesh>`, `<boxGeometry>`, and `<meshStandardMaterial>` to Three.js scene objects. `Canvas` creates/configures the scene, camera, renderer, sizing, and event layer. React components can then describe scene pieces; pointer events and React state can control slower interaction changes, while `useFrame` drives per-frame animation.
- **What the official source confirms:** In `Canvas.tsx`, the wrapper measures its parent, configures the render root and pointer event source, and accepts fallback DOM content when graphics support is missing. `hooks.tsx` implements `useFrame` by subscribing a callback to the scene loop and `useLoader` with Suspense-backed loading and caching. `loop.ts` runs subscribed frame callbacks and manages render scheduling. This source review explains the library architecture; no source code was copied into SIROSIU.
- **Useful paths for this project:** If React is selected and a design is approved, use the docs to learn the core renderer, load independently licensed GLTF models, and build a small interactive hero object or project viewer. Keep essential page text and controls in regular HTML outside the canvas, and provide a meaningful fallback. R3F does not provide a model catalogue or ready-made portfolio components; the Drei helpers, GLTF-to-JSX tooling, Three.js itself, and each model or texture are separate choices that need their own compatibility and license checks.
- **Performance and adoption:** The default canvas loop is continuous; the docs describe `frameloop="demand"` for scenes that can rest. They also cover invalidating frames when external controls mutate the scene, reusing geometry/materials, asset caching, instancing, staged loading, and performance-based quality changes. Treat these as techniques to measure on the target phone and desktop sizes, not a guarantee of fast rendering. The Canvas fallback helps when WebGL is unavailable, but does not by itself make a 3D scene keyboard-accessible.
- **License and reuse:** The official package manifest and repository license identify `@react-three/fiber` as MIT; redistribution of the library or substantial portions must retain its copyright and permission notice. Three.js, optional ecosystem packages, model files, textures, and the docs site's own media must be assessed separately. The reviewed documentation and source remain learning references only.

- **Source map:** [`src/App.tsx`](https://github.com/pmndrs/examples/blob/main/examples/gpgpu-curl-noise-dof/src/App.tsx) creates the R3F canvas, camera, autorotating OrbitControls, subtle CameraShake, and Leva controls; [`src/Particles.tsx`](https://github.com/pmndrs/examples/blob/main/examples/gpgpu-curl-noise-dof/src/Particles.tsx) creates and animates the point cloud; [`src/shaders/simulationMaterial.ts`](https://github.com/pmndrs/examples/blob/main/examples/gpgpu-curl-noise-dof/src/shaders/simulationMaterial.ts) initializes a float position texture and computes curl-noise motion in a fragment shader; [`src/shaders/dofPointsMaterial.ts`](https://github.com/pmndrs/examples/blob/main/examples/gpgpu-curl-noise-dof/src/shaders/dofPointsMaterial.ts) samples GPU positions and varies point size/opacity by focus distance. `size` defaults to 512, so the demo simulates 512 × 512 = 262,144 points.
- **How the GPU pipeline works:** A 512-square float `DataTexture` seeds positions throughout a sphere. Each frame, an offscreen framebuffer (`useFBO`) runs the simulation shader over the position texture, applying layered 3D curl-noise fields. The result texture is sampled by one `THREE.Points` draw call. The render shader calculates distance from the focus plane; aperture scales point blur size, while distance reduces opacity. `useFrame` eases uniforms toward the live control values. This is GPU simulation rather than a CPU loop moving thousands of DOM or Canvas circles.

Each trail follows the previous node with spring force, friction, damping, and tension. Quadratic curves smooth the points. Per frame, it clears the canvas, switches to `lighter` compositing, and strokes each line in an animated translucent HSL hue (`50%` saturation, `50%` lightness, `0.2` alpha). ## Saved cursor effect — Cursify Fluid Cursor

- **Live page and code tabs:** [Fluid Cursor page](https://cursify.ui-layouts.com/components/fluid-cursor), inspected in Brave on 2026-10-27. The page showed the React wrapper and a long `useFluidCursor` source panel, not a running effect preview. Read the TypeScript and JavaScript tabs; the code is plain JavaScript-shaped source in both, with no meaningful effect difference. Since the live page offered no demo, I did not claim to verify its visual output or click behavior directly.
- **What it renders:** This is a full-viewport, transparent WebGL fluid simulation, not a DOM cursor shape or a set of particles. Pointer movement injects colored velocity/dye into simulation textures; a sequence of GPU shader passes moves, diffuses, and shades the dye so it trails and swirls behind the pointer. The solver measures curl/vorticity, computes divergence and pressure, subtracts the pressure gradient to make velocity more fluid-like, advects velocity and color, then displays the resulting dye with optional shading. Clicking adds a separate stronger/randomly directed color-and-velocity splat. Hue is randomly generated and updated over time, so the effect cannot be set to a brand color through the supplied component.
- **Source map and setup:** The [`fluid-cursor.tsx` wrapper](https://github.com/ui-layouts/cursify/blob/main/registry/components/cursor/common/fluid-cursor.tsx) renders a fixed full-screen canvas with id `fluid` and calls the no-props [`use-FluidCursor.ts` hook](https://github.com/ui-layouts/cursify/blob/main/hooks/use-FluidCursor.ts). The hook contains roughly 1,160 lines of inline WebGL setup, shaders, framebuffer/double-buffer helpers, pointer handlers, and the animation loop. It tries WebGL 2, then WebGL 1/experimental WebGL. It has no dependency beyond browser WebGL; Tailwind classes in the wrapper control full-screen placement and click-through. The current configuration uses simulation resolution 128, dye resolution 1440, pressure iterations 20, curl 3, splat radius 0.2, splat force 6000, shading on, transparent canvas, and random color updates. The drawing buffer scales by device pixel ratio, so high-DPR screens can multiply the workload substantially.
- **Input and integration behavior:** The wrapper currently includes `pointer-events-none`, so the canvas should let page clicks pass through. However, the hook registers global `window` and `document.body` listeners for mouse down/move and touch start/move/end, including anonymous callbacks; it has no unmount cleanup for those listeners, animation frame, WebGL resources, or context. The hook starts the simulation loop on the first pointer movement and then schedules a new frame continuously. It provides no reduced-motion/visibility pause or touch-specific scroll policy. Its fixed canvas id and direct `document.getElementById` lookup make duplicate instances unsafe; it assumes the canvas and WebGL context exist and does not provide a graceful no-WebGL fallback.
- **Known click issue:** GitHub issue [#22](https://github.com/ui-layouts/cursify/issues/22) records a report that Fluid Cursor disabled click behavior. PR [#19](https://github.com/ui-layouts/cursify/pull/19), merged to `main` on 2026-02-03, changed pointer-event behavior and documentation. A later still-open issue [#25](https://github.com/ui-layouts/cursify/issues/25), opened 2025-07-29, reports clicks/links still stop working after selecting Fluid Cursor. We could not reproduce either report on this code-only page, so treat click-through behavior as a risk to verify in an actual integration.
- **Fit and reuse:** The GPU fluid-motion technique could inspire a small, tightly bounded colored trail, but the supplied full-screen high-resolution solver is heavier than a simple portfolio cursor and its event/lifecycle handling is unsuitable to transplant unchanged. If independently recreated, reduce dye resolution and DPR, scope the canvas and listeners, preserve click-through, support pointer events with deliberate touch behavior, pause when hidden/reduced-motion, and provide a non-WebGL fallback. The Cursify repository has no license file in the inspected GitHub view; its [open license request](https://github.com/ui-layouts/cursify/issues/21) remains the rights record. Do not copy or redistribute the code until reuse terms are clarified. No code or package was added to SIROSIU.
