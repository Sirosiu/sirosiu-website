# Roadmap

A phase is complete only when its exit conditions are met. GitHub Issues/Projects can track individual tasks once work items are ready; this roadmap stays at milestone level.

## 0. Project controls and workspace boundary — Complete

Create the shared project rules/docs and establish `site-next/` without changing existing app copies.

**Exit:** current source of truth is clear, historical decisions are marked, app boundary is documented.

## 1. Read-only audit and content intake — Next

Inventory existing copies and user-provided material. Verify project facts and identify missing content/assets. Collect the user's reference sites, repositories, models, and textures.

**Exit:** inventory records evidence and unknowns; no unlicensed assets or unverified claims are accepted.

## 2. Creative and experience definition

Explore distinct concepts, define the storytelling/content order, and select a direction with the user.

**Exit:** user-approved concept and content architecture; key alternatives and open items recorded.

## 3. Technical design

Choose the simplest implementation and asset approach that supports the approved experience; define acceptance checks and provisional measurable targets.

**Exit:** technical choices and trade-offs recorded; no unnecessary infrastructure.

## 4. Build `site-next/` prototype

Begins only when the user asks to start coding.

**Exit:** approved experience works across target sizes and core content remains available without optional graphics.

## 5. Independent review and refinement

Review visual evidence, content, responsive behavior, accessibility, loading, and performance. Fix findings and record actual verification.

**Exit:** agreed QA criteria pass and the user approves the candidate.

## 6. Release proposal

Verify real hosting/build configuration and prepare a preview/rollback plan. Production migration, deployment, and DNS changes require separate explicit authorization.
